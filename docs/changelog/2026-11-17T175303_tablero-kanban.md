## Antecedente

El desglose de las 39 tareas existía en
`sistema/historias-usuario/historias-usuario.md`, pero no había una vista de
ejecución: no se podía saber qué tarea estaba pendiente, en curso o
terminada sin leer el documento completo.

Se evaluaron Trello, Jira, GitHub Projects, Linear, Plane y las alternativas
autoalojadas (Kanboard, Vikunja, Wekan) por su plan gratuito, su exportación
en texto plano y el acceso de un agente de IA al tablero. Se descartaron
Trello y Jira porque su exportación es JSON o CSV y no texto; GitHub
Projects y Linear porque el tablero vive en la nube y exige una cuenta
externa; Plane porque su importador CSV no está en el plan gratuito. Se
eligió un **tablero Markdown dentro del repositorio**, que cumple las tres
condiciones a la vez: gratuito, texto plano y editable por el agente sin
intermediarios.

La decisión de fondo fue separar las responsabilidades: el documento manda
el **contenido** de cada tarjeta y el tablero manda el **estado**.

## Cambios de formato

No hubo cambios de formato en el informe, porque no se modificó ningún
archivo LaTeX. El tablero usa el formato del complemento Kanban de
Obsidian: encabezado `kanban-plugin: basic`, columnas con `##` y tarjetas
con `- [ ]`.

## Cambios de contenido

### Tablero

Se agregó `sistema/tablero/tablero.md` con las 39 tarjetas en cuatro
columnas: `Pendiente`, `En curso`, `En revisión` y `Hecho`. Cada tarjeta
lleva el identificador, el texto de la tarea, la historia, el responsable y
la prioridad y el riesgo heredados de la historia:

```markdown
- [ ] **T-HU-06.1** Crear una reserva desde la atención del personal o como solicitud del cliente, con su origen, el cliente, la salida y la cantidad de pasajeros. · HU-06 · A · Alta/Alto
```

La columna es el estado. La casilla `[ ]` no es un estado: la exigen los
visores para reconocer la tarjeta y el generador siempre la deja vacía. La
definición de terminado de cada tarjeta son los criterios de aceptación de
su historia, que siguen en el documento del backlog.

### Generador

Se agregó `sistema/tablero/generar.py`, sin dependencias fuera de la
biblioteca estándar. Antes de escribir:

1. Lee el desglose del documento y el CSV del backlog.
2. Comprueba que las historias coincidan, que cada historia tenga la misma
   cantidad de tareas en el documento y en el CSV, que la fila TOTAL del CSV
   coincida con la suma y que no haya identificadores repetidos.
3. Lee el tablero anterior y conserva la columna de cada tarjeta por su
   identificador.
4. Regenera el tablero en orden del backlog. Las tareas nuevas entran en
   `Pendiente`; las que ya no existen se avisan y se descartan.

Con `--check` no escribe: compara el contenido generado con el archivo y
devuelve código 1 si quedó desactualizado. Conserva los ajustes visuales que
escriben ambos complementos y el historial de movimientos de Boardwalk, y se
detiene si encuentra una tarjeta fuera de las columnas conocidas, en lugar
de perderla.

### Comandos

Se agregaron dos objetivos al `Makefile`:

```bash
make tablero            # regenera el tablero
make tablero-verificar  # comprueba que esté al día, sin escribir
```

### Requisitos de visualización

El tablero es Markdown: se lee y se edita **sin ninguna extensión**, y
GitHub o GitLab lo muestran como listas. Para la vista de columnas se
documentaron dos caminos gratuitos:

- **Obsidian**, gratis para uso personal: se abre la carpeta como bóveda y
  se instala **Boardwalk**, compatible con el formato y mantenido, o el
  **Kanban** original, sin mantenimiento desde 2024. Boardwalk es de
  escritorio por ahora; el original también funciona en móvil.
- **VS Code**: extensión **Unified Kanban**
  (`divisionseven.unified-kanban`), VS Code 1.85 o superior, desde el
  Marketplace o desde Open VSX.

Se aclaró que las otras extensiones de Kanban para VS Code (Kanban.md,
Kanban Markdown) usan formatos propios y no leen este tablero.

Además se corrigieron dos detalles que impedían abrirlo:

- El encabezado pasó de `kanban-plugin: board` a `kanban-plugin: basic`,
  que es el valor que reconoce el ecosistema de Obsidian y el que exige
  Unified Kanban.
- Las tarjetas pasaron de `- **T-HU…**` a `- [ ] **T-HU…**`, porque Unified
  Kanban solo reconoce tarjetas con casilla. Boardwalk y el Kanban original
  aceptan las dos formas.

### Corrección de T-HU-13.2

La tarea decía «…liberar el cupo una sola vez y verificar el nuevo saldo».
En una cancelación corresponde el cupo, no el saldo, que pertenece a HU-14.
Ahora dice «…verificar la nueva disponibilidad». El tablero se regeneró con
el texto nuevo. Los totales no cambian.

## Validación

- El tablero tiene 39 tarjetas: 20 del programador A y 19 del B, con el
  conteo por historia igual al del CSV.
- Se movió una tarjeta a `En curso` y se regeneró el tablero: conservó la
  columna. Al devolverla, el tablero volvió a coincidir.
- Se movió una tarjeta con la casilla marcada a `Hecho`: conservó la columna
  y la casilla volvió a quedar vacía, como corresponde.

  regenerar, la tarjeta se restauró.
- Se alteró la cantidad de tareas de HU-06 en una copia del CSV: el
  generador abortó con el detalle del desajuste y no escribió.
- Se agregaron los bloques `%% kanban:settings` y `%% boardwalk-history`: se
  conservaron al regenerar.
- Se verificó el formato contra el analizador de Unified Kanban, que exige
  `kanban-plugin: basic` y tarjetas con `- [ ]`, y contra el de Boardwalk,
  que acepta la casilla opcional y conserva el encabezado.
- `.vscode/extensions.json` se validó como JSON.
- `make tablero-verificar` informó «El tablero está al día».
- `make verificar` terminó con cero problemas: 26 archivos revisados, 20
  rutas LaTeX y 25 entradas del árbol del README.
- El PDF no se recompiló porque ningún archivo LaTeX cambió; conserva sus
  21 páginas.
